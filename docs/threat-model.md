# Threat Model: Windows Domain Security Lab

## 1. Methodology Overview

This document applies a simplified **Asset-Threat-Control** model tailored for a small home lab environment (`corp.lab`). It evaluates threat actors, trust boundaries, and specific threat scenarios against core Active Directory assets without requiring complex enterprise risk frameworks.

---

## 2. Step 1: Asset Identification

| Asset | Description | Lab Scope |
| :--- | :--- | :--- |
| **Domain Administrator Credentials** | Highly privileged credentials with administrative control across the entire domain. | `corp.lab\Administrator` |
| **Standard User Credentials** | Unprivileged identities used for normal day-to-day workstation sessions. | `corp.lab\testuser`, end-user accounts |
| **Active Directory Database** | The `NTDS.dit` database holding directory objects, schema, and password hashes. | Hosted on `DC01` |
| **Group Policy Objects (GPOs)** | Centralized configuration policies that enforce security settings across endpoints. | Default Domain Policy, Hardening GPOs |
| **Domain Controller** | Core server providing Active Directory Domain Services (AD DS) and Kerberos (KDC). | `DC01` (10.10.10.10) |
| **Client Workstation** | Domain-joined endpoint running Windows 11 used for day-to-day user tasks. | `CLIENT01` (10.10.10.100) |
| **Security Event Logs** | Windows event logs generated by endpoints, services, and directory operations. | Security log channel, WEC subscriptions |
| **Shared Folders** | SMB network shares containing departmental records, scripts, and business data. | Hosted on `FS01` / `DC01` shares |
| **Administrative Groups** | Built-in high-privilege groups that grant broad directory control. | `Domain Admins`, `Enterprise Admins`, `Schema Admins` |
| **DNS Service** | Core resolution service storing AD service location (`SRV`) records and name mappings. | Integrated on `DC01` |

---

## 3. Step 2: Threat Actor Profiles

- **Unauthorized External Individual**: External attacker attempting reconnaissance, brute forcing, or unauthorized ingress from outside the isolated network.
- **Malicious Standard Domain User**: Authenticated internal user attempting privilege escalation, internal reconnaissance, or unauthorized data access.
- **Compromised Workstation**: An endpoint under attacker control acting as a pivot point inside the `CORP-LAB` internal network.
- **Careless Administrator**: Legitimate administrator inadvertently introducing misconfigurations, weak permissions, or hygiene errors.
- **User with Excessive Privileges**: Legitimate user account provisioned with permissions exceeding actual operational needs.
- **Malware Operating Under a User Account**: Malicious binaries executing within unprivileged user space attempting persistence, credential harvesting, or lateral movement.

---

## 4. Step 3: Trust Boundaries

- **Between the Physical Host and Virtual Machines**: Hypervisor boundary separating the VirtualBox host OS from guest VMs in the internal virtual network (`CORP-LAB`).
- **Between Domain Users and Administrators**: Privilege boundary separating standard user identities from high-tier administrative accounts.
- **Between the Workstation and Domain Controller**: Endpoint separation boundary between user-facing endpoints (`CLIENT01`) and critical directory infrastructure (`DC01`).
- **Between Standard Users and Protected File Shares**: Access control boundary governed by NTFS permissions and security group memberships.
- **Between Event Sources and the Event Collector**: Log pipeline boundary separating event generation endpoints from central storage and monitoring repositories.

---

## 5. Step 4: Threat Scenarios & Assessment

### Evaluation Criteria

#### Likelihood Scale
- **Low**: Requires privileged access or uncommon conditions
- **Medium**: Feasible for an authenticated domain user
- **High**: Easily achievable with normal access

#### Impact Scale
- **Low**: Minimal interruption or exposure
- **Medium**: Affects one user or workstation
- **High**: Affects multiple users or sensitive resources
- **Critical**: Can compromise domain-wide trust or administration

---

### Threat Scenario Matrix

| ID | Threat scenario | Asset | Likelihood | Impact | Existing control | Residual risk |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **T-01** | Repeated password guessing | User accounts | Medium | Medium | Lockout policy | Account-related denial of service |
| **T-02** | Weak password selected | Credentials | Medium | High | Password policy | Predictable compliant passwords |
| **T-03** | Standard user gains local administrator access | Workstation | Medium | High | Restricted Groups | GPO misconfiguration |
| **T-04** | Privileged group membership modified | Domain | Low | Critical | Auditing and event monitoring | Delayed review |
| **T-05** | Security logs modified or deleted | Evidence | Low | High | Central event forwarding | Collector compromise |
| **T-06** | Unauthorized GPO modification | Domain endpoints | Low | Critical | Least privilege and auditing | Domain admin compromise |
| **T-07** | Unauthorized access to a departmental share | Business data | Medium | High | Group-based permissions | Incorrect group membership |
